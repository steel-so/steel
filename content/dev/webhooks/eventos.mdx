Todo evento chega com o mesmo envelope; muda só o `data`. Esta página mostra o
corpo **completo** de cada tipo, com os dados de exemplo que o `steel trigger`
também usa. Para receber e conferir as entregas, veja
[Receber os webhooks do Steel](/dev/webhooks/receber).

## O envelope

| Campo | Tipo | O que é |
| --- | --- | --- |
| `id` | texto | Id do evento (`evt_...`). O mesmo em todas as tentativas e no cabeçalho `Steel-Webhook-Id`: use para não processar duas vezes |
| `type` | texto | O tipo, como nas seções abaixo |
| `createdAt` | data ISO 8601 (UTC) | Quando o evento aconteceu no Steel. Use para ordenar: a ordem de chegada não é garantida |
| `workspaceId` | texto | O workspace de origem |
| `data` | objeto | O conteúdo do tipo |

Regras do `data`, as mesmas da [API v1](/dev/api-v1#estabilidade-e-depreciação):
campos novos e opcionais podem aparecer a qualquer momento (ignore o que não
conhece); nada é removido, muda de tipo ou passa a ser obrigatório sem um tipo
de evento novo e aviso prévio. Datas vêm sempre em UTC. Os campos `actorId`
são o id do usuário que fez a ação, ou `null` quando foi o sistema (uma
automação, o SLA, um canal externo).

O catálogo vivo, com os tipos dos módulos do seu token, está em
`GET /api/v1/webhooks/events` e em `steel webhooks events`.

| Tipo | Módulo |
| --- | --- |
| [`servicedesk.ticket.created`](#servicedeskticketcreated) | ServiceDesk |
| [`servicedesk.ticket.updated`](#servicedeskticketupdated) | ServiceDesk |

| [`servicedesk.contact.*`](#contatos-do-servicedesk) | ServiceDesk |

| [`crm.lead.created`](#crmleadcreated) | CRM |
| [`crm.opportunity.stage_changed`](#oportunidade-mudou-de-etapa) | CRM |
| [`crm.deal.won` e `crm.deal.lost`](#crmdealwon-e-crmdeallost) | CRM |
| [`crm.person.*` e `crm.company.*`](#pessoas-e-empresas-do-crm) | CRM |

## ServiceDesk

### servicedesk.ticket.created

Chamado aberto, por qualquer canal: aplicativo, portal, e-mail, WhatsApp,
monitoramento, API ou IA.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "servicedesk.ticket.created",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "ticket": {
      "id": "cm2tkt000000example",
      "number": 123,
      "code": "INC-000123",
      "title": "Impressora do financeiro sem conexão",
      "type": "INCIDENT",
      "channel": "PORTAL",
      "phase": {
        "id": "cm2phs000000example",
        "name": "Em atendimento",
        "category": "IN_PROGRESS"
      },
      "priority": {
        "id": "cm2pri000000example",
        "name": "Alta"
      },
      "departmentId": null,
      "assigneeId": "cm2usr000000example",
      "requesterId": null,
      "createdAt": "2026-10-18T12:00:00.000Z",
      "updatedAt": "2026-10-18T12:05:00.000Z"
    },
    "actorId": "cm2usr000000example"
  }
}
```

| Campo de `data.ticket` | O que é |
| --- | --- |
| `id`, `number`, `code` | Id, número e código com o prefixo do workspace (`INC-000123`) |
| `title` | Título |
| `type` | `INCIDENT`, `SERVICE_REQUEST`, `CHANGE` ou `PROBLEM` |
| `channel` | Por onde chegou: `AGENT`, `PORTAL`, `EMAIL`, `WHATSAPP`, `PHONE`, `AI` ou `API` |
| `phase` | Fase atual (`id`, `name`, `category`: `NEW`, `IN_PROGRESS`, `WAITING`, `RESOLVED`, `CLOSED` ou `CANCELED`) |
| `priority` | `{ id, name }` ou `null` |
| `departmentId`, `assigneeId`, `requesterId` | Ids, ou `null` |
| `createdAt`, `updatedAt` | Datas ISO 8601 |

Para o chamado completo (SLA, campos personalizados, descrição), busque
`GET /api/v1/servicedesk/tickets/{ticketId}` com o `data.ticket.id`.

### servicedesk.ticket.updated

Chamado alterado. Mesmo `ticket` do evento de abertura, já com os valores
novos, e `change` diz o que mudou: `fields` (campos), `assigned` (responsável)
ou `phase` (fase).

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "servicedesk.ticket.updated",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "ticket": {
      "id": "cm2tkt000000example",
      "number": 123,
      "code": "INC-000123",
      "title": "Impressora do financeiro sem conexão",
      "type": "INCIDENT",
      "channel": "PORTAL",
      "phase": {
        "id": "cm2phs000000example",
        "name": "Em atendimento",
        "category": "IN_PROGRESS"
      },
      "priority": {
        "id": "cm2pri000000example",
        "name": "Alta"
      },
      "departmentId": null,
      "assigneeId": "cm2usr000000example",
      "requesterId": null,
      "createdAt": "2026-10-18T12:00:00.000Z",
      "updatedAt": "2026-10-18T12:05:00.000Z"
    },
    "actorId": "cm2usr000000example",
    "change": "fields"
  }
}
```

Uma mudança de responsável também gera `servicedesk.ticket.assigned`; uma
resolução, `servicedesk.ticket.resolved`. Assine só o que o seu sistema usa
para não tratar o mesmo fato duas vezes.

### Avisos do chamado

Os tipos abaixo têm o mesmo formato: uma referência curta ao chamado
(`id`, `number`, `code`, `title`), o `actorId` e um `summary` com o título e o
texto da notificação, em português. O `summary` é feito para mostrar a uma
pessoa (num canal do Teams, num SMS); não faça o seu código depender dele.

| Tipo | Quando | `summary.title` de exemplo | `summary.body` de exemplo |
| --- | --- | --- | --- |
| `servicedesk.ticket.assigned` | Chamado atribuído a um atendente. | Chamado atribuído a você | INC-000123 — Impressora do financeiro sem conexão |
| `servicedesk.ticket.message` | Nova mensagem pública no chamado. | Nova mensagem no chamado | A impressora voltou a funcionar, obrigado! |
| `servicedesk.ticket.resolved` | Chamado resolvido. | Chamado resolvido | INC-000123 foi resolvido. |
| `servicedesk.ticket.reopened` | Chamado reaberto. | Chamado reaberto | INC-000123 foi reaberto pelo solicitante. |
| `servicedesk.ticket.escalated` | Chamado escalonado por regra ou manualmente. | Chamado escalonado | INC-000123 foi escalonado para o nível 2. |
| `servicedesk.ticket.csat` | Solicitante avaliou o atendimento (CSAT). | Avaliação recebida | Nota 5 de 5. |
| `servicedesk.sla.at_risk` | SLA do chamado em risco. | SLA em risco | Faltam 30 minutos para vencer a resolução. |
| `servicedesk.sla.breached` | SLA do chamado violado. | SLA violado | O prazo de resolução venceu. |
| `servicedesk.approval.requested` | Aprovação solicitada no chamado. | Aprovação solicitada | A mudança aguarda a sua aprovação. |
| `servicedesk.approval.responded` | Aprovação respondida (aprovada ou recusada). | Aprovação respondida | A mudança foi aprovada. |

Exemplo, `servicedesk.sla.at_risk`:

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "servicedesk.sla.at_risk",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "ticket": {
      "id": "cm2tkt000000example",
      "number": 123,
      "code": "INC-000123",
      "title": "Impressora do financeiro sem conexão"
    },
    "actorId": "cm2usr000000example",
    "summary": {
      "title": "SLA em risco",
      "body": "Faltam 30 minutos para vencer a resolução."
    }
  }
}
```

### Clientes e empresas do ServiceDesk

`servicedesk.customer.created`, `servicedesk.customer.updated` e
`servicedesk.customer.deleted`. Saem em qualquer caminho: tela, importação de
planilha ou [API v1](/dev/api-v1/cadastros). No `deleted`, o `customer` é o
último estado antes da exclusão.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "servicedesk.customer.created",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "customer": {
      "id": "cm2cus000000example",
      "kind": "COMPANY",
      "personType": "LEGAL",
      "name": "Acme Ltda",
      "tradeName": "Acme",
      "document": "12345678000190",
      "email": "contato@acme.com.br",
      "phone": "1130000000",
      "whatsapp": "5511999990000",
      "city": "São Paulo",
      "state": "SP",
      "active": true,
      "createdAt": "2026-10-18T12:00:00.000Z",
      "updatedAt": "2026-10-18T12:05:00.000Z"
    },
    "actorId": "cm2usr000000example"
  }
}
```

| Campo de `data.customer` | O que é |
| --- | --- |
| `kind` | `CLIENT` (pessoa) ou `COMPANY` (empresa) |
| `personType` | `INDIVIDUAL` (CPF) ou `LEGAL` (CNPJ) |
| `document` | CPF/CNPJ só com dígitos, ou `null` |
| `phone`, `whatsapp` | Só dígitos; o WhatsApp com DDI |
| `active` | `false` para cadastro inativo |

Notas internas e campos personalizados **não** vão no evento: busque
`GET /api/v1/servicedesk/customers/{customerId}`.

### Contatos do ServiceDesk

`servicedesk.contact.created`, `servicedesk.contact.updated` e
`servicedesk.contact.deleted`, com o mesmo critério dos clientes.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "servicedesk.contact.created",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "contact": {
      "id": "cm2sct000000example",
      "name": "Carlos Lima",
      "jobTitle": "Analista de TI",
      "email": "carlos@acme.com.br",
      "phone": null,
      "whatsapp": "5511988887777",
      "userId": null,
      "active": true,
      "customerIds": [
        "cm2cus000000example"
      ],
      "createdAt": "2026-10-18T12:00:00.000Z",
      "updatedAt": "2026-10-18T12:05:00.000Z"
    },
    "actorId": "cm2usr000000example"
  }
}
```

`data.contact.customerIds` lista os clientes/empresas vinculados (o principal
primeiro). `userId` é o usuário da plataforma que é este contato, ou `null`.

### Base de conhecimento

`servicedesk.kb_article.created` (nasce como rascunho),
`servicedesk.kb_article.updated`, `servicedesk.kb_article.published`,
`servicedesk.kb_article.unpublished` (voltou para rascunho ou revisão) e
`servicedesk.kb_article.deleted`.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "servicedesk.kb_article.published",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "article": {
      "id": "cm2kba000000example",
      "title": "Como redefinir a senha da VPN",
      "status": "PUBLISHED",
      "visibility": "PORTAL",
      "parentId": null,
      "categoryId": null,
      "tags": [
        "vpn",
        "acesso"
      ],
      "sourceTicketId": null,
      "publishedAt": "2026-10-18T12:05:00.000Z",
      "createdAt": "2026-10-18T12:00:00.000Z",
      "updatedAt": "2026-10-18T12:05:00.000Z"
    },
    "actorId": "cm2usr000000example"
  }
}
```

O evento traz os metadados, **sem o conteúdo**: busque
`GET /api/v1/servicedesk/kb/articles/{articleId}`. O salvamento automático do
editor (só o texto) não gera `updated`; mudar título, categoria, visibilidade
ou tags, sim. Arquivar e restaurar um artigo também não geram evento.

## CRM

### crm.lead.created

Novo lead, por qualquer canal: aplicativo, formulário, API de integração,
API v1, importação ou IA.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "crm.lead.created",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "lead": {
      "id": "cm2lead00000example",
      "name": "Maria Souza",
      "emails": [
        "maria@example.com"
      ],
      "phones": [
        "+5511999990000"
      ],
      "company": "Acme Ltda",
      "source": "site",
      "channel": "FORM",
      "score": 40,
      "ownerId": null,
      "createdAt": "2026-10-18T12:00:00.000Z"
    }
  }
}
```

| Campo de `data.lead` | O que é |
| --- | --- |
| `emails`, `phones` | Listas; pelo menos uma delas tem item |
| `source`, `channel` | Origem e canal informados, ou `null` |
| `score` | Pontuação calculada na entrada |
| `ownerId` | Dono escolhido pelas regras de roteamento, ou `null` |

### Oportunidade mudou de etapa

Tipo `crm.opportunity.stage_changed`. A oportunidade mudou de etapa (no quadro,
pela API v1 ou pela IA). `category` da etapa é `OPEN`, `WON` ou `LOST`.
`fromStage` vem `null` quando a etapa anterior não existe mais.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "crm.opportunity.stage_changed",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "opportunity": {
      "id": "cm2opp000000example",
      "name": "Renovação do contrato de suporte",
      "amount": 12000,
      "pipelineId": "cm2pip000000example",
      "ownerId": "cm2usr000000example"
    },
    "fromStage": {
      "id": "cm2stg00000example1",
      "name": "Proposta",
      "category": "OPEN"
    },
    "toStage": {
      "id": "cm2stg00000example2",
      "name": "Negociação",
      "category": "OPEN"
    },
    "actorId": "cm2usr000000example"
  }
}
```

### crm.deal.won e crm.deal.lost

Negócio ganho ou perdido. `source` diz de onde veio: `lead` (um lead fechado
como ganho ou perdido) ou `opportunity` (uma oportunidade que entrou numa etapa
de categoria `WON` ou `LOST`). Uma oportunidade que vai para uma etapa de ganho
gera os dois eventos: `crm.opportunity.stage_changed` e `crm.deal.won`. Andar
entre duas etapas de ganho não gera um segundo `crm.deal.won`.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "crm.deal.won",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "source": "opportunity",
    "id": "cm2opp000000example",
    "name": "Renovação do contrato de suporte",
    "amount": 12000,
    "ownerId": "cm2usr000000example",
    "actorId": "cm2usr000000example"
  }
}
```

`crm.deal.lost`, vindo de um lead:

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "crm.deal.lost",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "source": "lead",
    "id": "cm2lead00000example",
    "name": "Renovação do contrato de suporte",
    "amount": 12000,
    "ownerId": "cm2usr000000example",
    "actorId": "cm2usr000000example"
  }
}
```

`amount` é o valor do negócio, ou `null` quando não foi informado.

### Pessoas e empresas do CRM

`crm.person.created`, `crm.person.updated`, `crm.person.deleted` e os três
equivalentes de empresa (`crm.company.*`). Saem por qualquer caminho: tela,
importação, formulário ou [API v1](/dev/api-v1/cadastros). No `deleted`, o
registro é o último estado antes da exclusão (que é lógica no Steel).

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "crm.person.created",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "person": {
      "id": "cm2per000000example",
      "name": "Maria Souza",
      "emails": [
        "maria@example.com"
      ],
      "phones": [
        "+5511999990000"
      ],
      "city": "São Paulo",
      "jobTitle": "Gerente de TI",
      "companyId": "cm2cmp000000example",
      "createdAt": "2026-10-18T12:00:00.000Z",
      "updatedAt": "2026-10-18T12:05:00.000Z"
    },
    "actorId": "cm2usr000000example"
  }
}
```

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "crm.company.updated",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "company": {
      "id": "cm2cmp000000example",
      "name": "Acme Ltda",
      "cnpj": "12345678000190",
      "domain": "acme.com.br",
      "employees": 120,
      "arr": 240000,
      "icp": true,
      "accountOwnerId": "cm2usr000000example",
      "createdAt": "2026-10-18T12:00:00.000Z",
      "updatedAt": "2026-10-18T12:05:00.000Z"
    },
    "actorId": "cm2usr000000example"
  }
}
```

| Campo | O que é |
| --- | --- |
| `person.emails`, `person.phones` | Listas, na ordem do cadastro |
| `person.companyId` | Empresa do CRM vinculada, ou `null` |
| `company.cnpj` | Só com dígitos, ou `null` |
| `company.arr` | Receita anual recorrente em reais, ou `null` |
| `company.icp` | `true` se está no perfil de cliente ideal |
| `company.accountOwnerId` | Dono da conta, ou `null` |

Campos personalizados, LinkedIn e avatar **não** vão no evento: busque o
registro em `GET /api/v1/crm/people/{personId}` ou
`GET /api/v1/crm/companies/{companyId}`.

### Documentos

`crm.document.created`, `crm.document.updated`, `crm.document.deleted`,
`crm.document.sent` (enviado a um ou mais destinatários, com `recipients`),
`crm.document.accepted` e `crm.document.declined` (o leitor respondeu pelo
link público).

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "crm.document.sent",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "document": {
      "id": "cm2doc000000example",
      "title": "Proposta comercial - Acme",
      "ownerId": "cm2usr000000example",
      "kind": "PROPOSAL",
      "status": "SENT",
      "isTemplate": false,
      "companyId": "cm2cmp000000example",
      "personId": null,
      "opportunityId": "cm2opp000000example",
      "leadId": null,
      "totalValue": 12000,
      "validUntil": "2026-11-18T12:00:00.000Z",
      "sentAt": "2026-10-18T12:05:00.000Z",
      "acceptedAt": null,
      "createdAt": "2026-10-18T12:00:00.000Z",
      "updatedAt": "2026-10-18T12:05:00.000Z"
    },
    "actorId": "cm2usr000000example",
    "recipients": 1
  }
}
```

Aceite e recusa não têm `actorId`: quem responde é o leitor do link, descrito em
`reader`.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "crm.document.declined",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "document": {
      "id": "cm2doc000000example",
      "title": "Proposta comercial - Acme",
      "ownerId": "cm2usr000000example"
    },
    "reader": {
      "name": "Maria Souza",
      "email": "maria@example.com"
    },
    "reason": "Fora do orçamento deste trimestre."
  }
}
```

| Campo | O que é |
| --- | --- |
| `document.kind` | `PROPOSAL`, `CONTRACT`, `QUOTE`, `PRESENTATION`, `TERMS`, `REPORT` ou `OTHER` |
| `document.status` | `DRAFT`, `SENT`, `VIEWED`, `ACCEPTED`, `DECLINED`, `EXPIRED` ou `ARCHIVED` |
| `document.companyId`, `personId`, `opportunityId`, `leadId` | Vínculos com o CRM, ou `null` |
| `document.totalValue` | Valor total em reais, ou `null` |
| `reader.email` | E-mail do leitor, ou `null` quando o link era genérico e ele não informou |
| `reason` | Motivo da recusa; `null` no aceite |

O conteúdo do documento, os destinatários e os links **não** vão no evento. O
salvamento automático do editor também não gera `updated`.

## Comunicação

### communication.message.received

Mensagem de WhatsApp recebida de um contato numa conexão da Comunicação.
Mensagens que chegam por uma conexão ligada ao ServiceDesk viram mensagens do
chamado e **não** geram este evento.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "communication.message.received",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "message": {
      "id": "cm2msg000000example",
      "conversationId": "cm2cnv000000example",
      "type": "TEXT",
      "text": "Olá, gostaria de um orçamento.",
      "providerMessageId": "wamid.example",
      "receivedAt": "2026-10-18T12:00:00.000Z"
    },
    "contact": {
      "id": "cm2ctt000000example",
      "waId": "5511999990000",
      "name": "Maria"
    },
    "connectionId": "cm2con000000example"
  }
}
```

| Campo | O que é |
| --- | --- |
| `message.type` | `TEXT`, `IMAGE`, `AUDIO`, `VIDEO`, `DOCUMENT`, `STICKER`, `LOCATION`, `BUTTON`, `CONTACT`... |
| `message.text` | O texto, ou a legenda da mídia; `null` quando não há |
| `message.providerMessageId` | Id da mensagem no provedor (`wamid...` na Meta) |
| `contact.waId` | Número do WhatsApp só com dígitos (DDI + DDD + número) |
| `connectionId` | A conexão que recebeu |

A mídia não vem no evento. Abra a conversa no Steel pelo `conversationId`.

### communication.conversation.waiting

Uma conversa da Comunicação **entrou na fila**, aguardando um atendente:
aberta, não arquivada e sem responsável — a mesma regra de
[`GET /api/v1/whatsapp/conversations/waiting`](/dev/api-v1/comunicacao#conversas-aguardando-atendimento).
O evento sai uma vez por entrada na fila, não a cada mensagem nova de uma
conversa que já está nela.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "communication.conversation.waiting",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "conversation": {
      "id": "cm2cnv000000example",
      "status": "NEW",
      "connectionId": "cm2con000000example",
      "teamId": null,
      "aiActive": false,
      "unreadCount": 1,
      "lastMessageAt": "2026-10-18T12:00:00.000Z",
      "createdAt": "2026-10-18T12:00:00.000Z"
    },
    "contact": {
      "id": "cm2ctt000000example",
      "waId": "5511999990000",
      "name": "Maria"
    },
    "reason": "new",
    "actorId": null
  }
}
```

| Campo | O que é |
| --- | --- |
| `reason` | `new`: o contato abriu uma conversa nova; `reopened`: uma conversa fechada foi reaberta (pelo contato ou por um atendente) sem responsável; `returned_to_queue`: o responsável saiu (devolvida para a fila, ou um botão de resposta a moveu para a fila de uma equipe) |
| `conversation.teamId` | Fila da equipe em que a conversa espera; `null` = fila geral |
| `conversation.aiActive` | `true` quando a IA está respondendo enquanto ninguém assume |
| `actorId` | Quem devolveu ou reabriu; `null` quando foi o contato ou uma automação |

Conversas de conexões ligadas ao ServiceDesk viram chamados e **não** geram
este evento. Uma conversa **nova** aberta do lado da empresa (por um atendente, no
Steel ou pelo celular, ou por um envio da API) também não gera, mesmo sem
responsável: o evento avisa quando um **contato** passa a esperar.

### agents.approval.pending

## Plataforma

### steel.ping

O evento do botão **Enviar teste** (e de `POST /api/v1/webhooks/endpoints/{id}/test`).
Vai só para aquele endpoint, nunca entra numa assinatura e não conta para a
desativação automática.

```json
{
  "id": "evt_cm2x7k3p0000abcd",
  "type": "steel.ping",
  "createdAt": "2026-10-18T12:00:00.000Z",
  "workspaceId": "cm2ws0001",
  "data": {
    "message": "Teste de webhook do Steel"
  }
}
```

Responda `2xx` ao `steel.ping` como a qualquer outro evento: é assim que o
teste confirma que a URL e a assinatura estão certas.
